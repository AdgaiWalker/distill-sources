首先这是kimi自己总结的，质量不是很好，发出来只是提供一下思路上的交流。

这份文档自包含,交给另一个 AI 即可复现整套机制。 它不是设计稿,是跑了 一个月、被几十次事故修过的生产系统的写实。 先读「0. 现实预期」再动手——这套系统的价值在管道,不在魔法。

0. 现实预期(必须先说清)

•
WordPress 5.3+ 评论链接默认 rel="ugc nofollow" 。 评论腿基本产不出 dofollow ,它的真实价值是:引流、链型多样性、品牌提及。要 dofollow 主粮请走目录提交/客座博客(不在本文范围)。
•
投出(WP 302 受理)≠ 上线。实测:投出的评论终核存活率 0~5%(大博主会事后清扫)。 KPI 只认终核在线的链,账面「投达」一律视为幻觉资产。
•
规模化(每天上百条)必然触发反垃圾(Akismet 全局学习、CleanTalk 封数据中心 IP 段)。系统按「低频、像人、可证伪」设计,不要按「冲量」设计。

五个进程级组件,各自独立可换:

1.
采集 (任何方式填满目标池即可,接口 = 往 quality_resources 写行);
2.
滚动驱动 :从池里选目标、轮换出口 IP、逐站调投放器,循环不止;
3.
投放器 agent_submit :LLM 在环的浏览器自动化,单站一次 run,终局落库;
4.
核验器 verify_link :过一天后回头查「链到底在不在、rel 是什么」;
5.
人机协同 (可选):投不了的站进人工队列,Chrome 插件辅助人完成。

3. 选品(比投放更决定成败)

驱动从池里选目标时的过滤与优先级:

1.
狙击优先(实证评论区开放) :先把竞品反链里「评论真实在页」的站挖出来(抓竞品反链来源页,机械判定链接在评论容器里),这些站的「那条竞品评论所在的帖子 URL」就是首选靶——评论区开放是实证的;
2.
池子过滤:只投 cs=form (预审确认有原生评论表单,Disqus/Facebook iframe 要账号的不投)、 cmts>0 (有已批准评论 = 博主会审)、近一两年的新帖;
3.
排除: site_constraints 未过期者、本产品 submissions 已有记录者(不重打);
4.
每波按域去重 (池子一域多行)。

4. 投放器(agent_submit)— LLM 在环的浏览器自动化

形态:Node + playwright-core(系统 Chrome, headless)+ 一个 LLM 网关。每站一次 run: 打开页面 → LLM 观察(DOM 摘要+截图可选)→ 动作(fill/click/solve/giveup)→ 终局落库。

4.1 预算与终局(防止死磕 = 防止烧钱)

•
步数预算 ~24 步、单站时间预算 ~10 分钟,烧尽按 blocked 记;
•
终局六态: pending_review (接口确认受理)/ success (页面确认上线)/ blocked (卡点,带精确归因)/ skipped_fit (类目不匹配)/ skipped_paid (收费墙)/ emailed (站内联系表单提交成功且回执可见—— 严格定义,谎称发过邮件=最严重违规 );
•
失败 36% 的步数耗在逐字段 fill 上 → fill_many 一次填多字段 ,提交按钮单独 click;
•
连续 N 步页面无变化(URL/正文/字段数不动)判定卡死,立即终局;
•
过不去的站进 人工队列 (human_tasks),不阻塞主循环。

4.2 表单识别(实战要点)

•
评论表单可能在跨域 iframe(Jetpack): allFrames 注入 ,主框架先把 iframe 滚进视口触发懒渲染,各 frame 轮询等表单 ≤8s;
•
新版 wordpress.com 评论是 contenteditable 块编辑器,不是 textarea:detect 要有 contenteditable 回退,写值走 execCommand('insertText') (Gutenberg 才能感知);
•
字段定位用「label 回退链」:label[for] → 包裹 label → aria/placeholder → name → id,多语言词表(英/法/西/葡/德);
•
蜜罐字段靠可见性过滤(display/visibility/opacity/尺寸)排除;
•
定位到评论框后,把 name/email/url 的搜索范围收窄到同一个 <form> ——否则页首的 newsletter 订阅框会被误填。

4.3 验证码

•
reCAPTCHA/Turnstile 走 solver API(CapSolver 类); 幻影 sitekey (页面没真组件)直接跳过解码、裸提交试——很多站是服务端隐形防护;
•
solver 返回幻影 key 错误(ERROR_INVALID_TASK_DATA)要兜住进人工队列,不许打穿整站;
•
solver 出口 IP 与浏览器出口 IP 不一致时,严格站会判 token 无效——要么 Proxyless 裸试,要么给 solver 配同出口代理;
•
判了 captcha_unsolvable 的站记约束(14 天不重试),不重复烧。

5. 反检测三件套(全都实证过)

1.
Persona 池 (8 个真人感姓名+gmail 邮箱):同域 hash 固定抽同一个(同域同人,跨域轮换)。 邮箱域必须 ≠ 被推广域 ——用产品域邮箱发评论等于向 Akismet 自报家门;评论流程不回信,邮箱无需受控(需要收信的注册流程走受控邮箱);
2.
作者网址落点轮换 :主域 50% / 卫星内容站(Substack/Blogspot)25%+25%,同域稳定——几百条评论全指同一个新域是 spam 签名;
3.
内容结构打散 :LLM 写评论时 few-shot 样本随机抽 + 结构权重轮换(正常带产品/纯读后感不带产品/带问题/短评),禁止全网一个模板。

另加: 每站轮换出口 IP (见《mihomo-rotate.md》:PUT 控制器换节点 + ipify 实证 + 死节点跳过+连续全死才中止); 禁止点击 mailto: (会唤起 OS 邮件客户端——prompt 禁令 + DOM 捕获层硬拦双保险);stealth UA/语言/时区自洽。

6. 评论内容生成

•
每篇文章 现写 :抓正文前 ~2500 字给 LLM,要求引用文章具体细节(审核博主就看这个);
•
正文绝不放链接 (博主秒删),链接只走 website 字段;名字字段用真人全名,绝不用关键词(Google spam policy 明文);
•
浏览器翻译态检测 :页面被 Chrome 翻成中文时禁止生成(会写中文评论贴英文站,一眼 spam),提示切回原文。

7. 核验器(verify_link)— 账本的唯一真相源

投出后 ≥8~24h 回头核, 四路探针 : recorded_url(记录的页面) → sitemap(全站 URL 清单) → site_search(站内搜索) → path_guess(路径枚举) 。

•
三态严格: online / offline_confirmed (确实找过且没有)/ unknown_* (网络问题绝不写"未上线");
•
WP 评论分页:首页没有要翻到最后一页 (新评论在末页);
•
rel 必须在评论的规范位置读 ——站内搜索页/侧栏「最新评论 widget」里的回显锚不带 rel,采信会把 ugc nofollow 错记成 dofollow:命中页上找「与目标锚同一容器」的评论 permalink,跳回去重读;锚选择优先级 = 评论作者链(class=url) > 带 rel 的显式标记 > 无 rel 回显;
•
结果写 verification_runs(append-only)+ 更新 link_facts; 记分牌只从 link_facts 出 。

8. 滚动驱动与运维制度

•
循环:每波评论 40 + 目录 25,两池空就睡 1 小时;死节点跳过,连续 8 个节点全死睡 10 分钟自愈,不硬闯;
•
每日两 cron:早上采集波(补池)+ 早上终核波(核昨天投出的);
•
成本全记 cost_events(provider/job/金额),$每计入链 是唯一效率指标;
•
headless 浏览器僵尸:包装超时/杀进程会留孤儿 Chrome,定期清扫(按启动参数区分自动化实例 vs 用户实例)。

9. 复现清单(另一个 AI 需要准备的)

1.
SQLite + 第 2 节的表;
2.
一个 LLM 网关(便宜模型做预审/采集,强模型写评论和开车);
3.
Node + playwright-core + 一个浏览器;投放器按第 4 节的预算/终局/表单/验证码规则写;
4.
出口代理池(mihomo 或等价物,API 可换节点即可);
5.
Persona 池 json([{name,email}]) + 产品 kit json({name,url,taglines,descriptions,tags});
6.
核验器按第 7 节的探针/分页/rel 规则写;
7.
两 cron + 写库 autocommit 纪律。

可选增强:solver 账号(验证码)、Chrome 插件人机协同队列、SimilarWeb 类数据源(采集竞品反链做狙击手名单——没有也能跑,用 footprints 搜 "niche + leave a comment" 建池)。

10. 已验证的失败模式(别重踩)

•
投达当资产(pending_review 幻觉);
•
邮箱域=产品域(自报家门);
•
数据中心 IP 硬闯(CleanTalk 按段封);
•
同一模板全网发(Akismet 全局学习);
•
核验读 widget 回显的 rel(dofollow 错记);
•
长事务写库(全库锁死);
•
无限重试验证码(烧钱换 0)。

A.3 表单识别与写入(浏览器层)

•
蜜罐:注入侧按 display/visibility/opacity/尺寸做可见性过滤;
•
写值: focus → native setter(HTMLInputElement.prototype.value.set) → dispatch InputEvent + change ——原生与 React 受控组件通吃;contenteditable 走 execCommand('insertText') ;
•
先定位评论框,再把其余字段的搜索范围收窄到同一个 <form> (防误填页首订阅框);iframe 内找不到才放宽到全 document;
•
label 回退链: label[for] → 包裹 label → aria-label → placeholder → name → id;多语言词表 name=author/name/nickname/nom/nombre/nome, email=email/e-mail/mail/courriel/correo, url=url/website/homepage/web。

A.4 验证码处理细节

•
sitekey 提取:先 document.querySelector('[data-sitekey]') (连 action 一起拿),再正则 (0x4AAAAAAA[A-Za-z0-9_-]{5,}) 从 HTML 捞(Turnstile);
•
api2/aframe 是空壳 iframe :reCAPTCHA 的 iframe 只有带 k= 参数的才是真挑战;幻影 key(sitekey 提取无效)直接裸提交,不死磕解码;
•
reCAPTCHA api2 widget 会在表单提交瞬间清掉 g-recaptcha-response—— token 注入后立刻提交 ,中间别插别的动作;
•
solver 任务幻影 key 错误(ERROR_INVALID_TASK_DATA)→ 进人工队列,不 EXC 打穿整站;
•
判 captcha_unsolvable → site_constraints 记 14 天。

A.5 评论内容生成(api_compose)

kit 里带 comment_voice: {tone:[], few_shots:[{scene,text}]} 。生成规则:

•
few_shots 随机抽 2 条 (固定前 N 条 = 结构指纹);
•
结构权重轮换:normal(0.4)/no_product(0.2,全文不提产品)/no_question(0.2)/short(0.2);
•
硬约束:1-3 句、第一人称、≤60 词、引用文章具体细节、正文不放链接、禁通用好评/营销腔;
•
输入:页面正文截选 ~2500 字;浏览器翻译态(documentElement.class 含 translated-ltr/rtl)直接拒绝生成。

A.6 核验探针细节

•
sitemap 发现 :先读 /robots.txt 的 Sitemap: 行,再补 /sitemap.xml 、 /sitemap_index.xml 、 /sitemap-index.xml 、 /wp-sitemap.xml ,及 www 变体;BFS 展开 sitemap index,抓取上限 25 次、命中上限 5 个;
•
站内搜索候选 : /search?q= 、 /?s= 、 /?q= 、 /search/<slug> 、 /search?query= 、 /search?keyword= ;
•
锚提取 :页面上所有 a[href],hostname endswith 产品域 = direct; /go|out|visit|redirect|link|ref|away 或 ?url=/to=/target=/redirect= 的算 redirectish,跟随跳转解析;正文提到产品名且有 redirectish 时才跟随(省请求);
•
锚选择打分 (修过的):评论作者链(class 含 url)=0 优先 > 带 rel 的 > 无 rel 回显 > 再按 nofollow 罚分和锚文本长度;
•
indexable :meta[name=robots] 与 X-Robots-Tag 头查 noindex; dofollow :锚 rel 不含 nofollow/ugc/sponsored 且页面不是整页 nofollow;
•
offline_confirmed 的门槛必须高于判活 :sitemap 可读(拿到全站清单)或 ≥10 个明确 HTTP 结论的页面,否则记 unknown_blocked 不判死。

A.7 池子预审(prescreen)

每个候选 URL 抓一次,输出:

•
comment_system 三分:页面有评论 textarea = form ;只有 Disqus/Facebook/Verbum iframe = iframe (要账号,不投);皆无 = none ;
•
comment_count :评论块计数(class 含 comment 的容器),cmts>0 = 博主会审的实证;
•
author_linked :评论区作者是否带外链(有 = 允许作者网址);
•
入池纪律: blog_comment 只收 cs=form;iframe/none 的不收(收也是白跑)。
