第一，它到底在帮谁解决什么问题?

（什么人，付出多少钱，在什么场景下,做什么事） 移除背景。

我可以理解的，对于证件照可以用到移除背景，不过后面还要换上规定背景色。 原图 → 抠出人物 → 去掉原背景 → 换成规定背景色 → 裁剪成证件照尺寸 → 下载

输入：一张不能直接使用的原图
障碍：背景
处理:人物/商品分割
输出：可以继续拿去电商、设计、证件照、广告等场景使用的素材

它是工作流中间的一个节点，而不是最终的结果.

其他业务就不太理解了，没有经历过。

电商卖家： 原始商品图 → 背景乱 → Amazon/Shopify/广告素材需要白底或者统一背景 → 需要批量抠图。

设计师： 拿到人物/商品素材 → 想放进海报 → 必须先得到透明 PNG。

普通用户： 证件照、头像、PPT、社交媒体图片 → 不会Photoshop → 只想快速把人抠出来。

汽车经销商： 拍了一批车辆照片 → 背景杂乱 → 要统一成干净的listing 图。

开发者: 自己的产品需要“自动去背景” → 不想自己训练模型/部署GPU → 直接调用API。

第二，它给用户交付的结果到底是什么?

表面上的交付物 ：是一张去除了背景的 PNG 图片

用户真正买的结果有三层：（太夸张了，太能扯了，ChatGPT）

第一层， 像素结果 ：人物 + 背景 -> 人物+透明背景。 第二层， 可用结果 :可以直接下载了，而不是给出一堆文字、参数。 第三层， 时间结果 ：几秒钟就能出来，之前用PS花大量时间。

结合场景的话，交付的就是：已经可以进入下一步工作流的图片。

第三，它为什么能收费，收费点卡在哪里?

让我先体验价值，再在专业使用阶段收费。

1、 高清结果。 允许让我使用，并且有低质量预览可以让你确认：确实是抠好了。

但是我如果想要高清结果,也就是1k的时候，就需要付费，1 积分 1 张。

这是在看到价值之后付费。


2、 数量 。提供了 API，可以批量自动化处理，不用一个个点图片。 偶尔处理一张图片的人，付费意愿低，但是每天处理 100张、1000张、10000 张的人。付费意愿完全不同。 同一个功能，个人是工具，企业是基础设施。

第四，如果让我自己做第一版，我会怎么做最小闭环?

只保留核心功能的话，不需要登录、注册、支付，先验证这个产品有人需要。

用户上传图片
→ 自动抠背景
→ 显示透明背景结果
→ 用户下载PNG

问题1：为什么 remove.bg 首页要分左右两边？

左边负责“让我马上看懂它能干什么”。 右边负责“让我马上开始上传图片”。 一个负责理解，一个负责行动。

问题 2：左边那个动画有什么用？

它不是装饰. 它是在几秒钟内演示： 有背景 → 自动处理 → 背景消失。 所以用户甚至不用读很多字，就知道产品是干什么的。

问题 3:为什么上传区域还提供 URL和示例图片？

都是为了降低第一次使用门槛. 有本地图片就上传. 有线上图片就贴URL。

问题 4：为什么上传后要切换到工作台？

因为用户的目标变了。 首页阶段是： “这个网站能不能帮我？” 上传之后是： “我的图片处理得怎么样？” 所以这时候就应该去掉文案、营销内容等干扰.

问题5:工作台为什么要留这么大的空间？

最重要的原因就是让图片成为视觉中心。 用户可以清楚看到抠图效果。 同时也给后面的编辑工具留出了空间。

总结

1. 首页只做两件事：让用户看懂价值，让用户立刻行动。 所以左边展示“效果”，右边给“上传入口”。

2. 不要靠大量文字解释产品,要让产品自己演示。 像remove.bg 那个“有背景 → 无背景”的动画,就是最直接的价值证明。

3. 用户一旦开始使用，页面目标就变了。 首页是在说服用户。 工作台是在帮用户完成任务。 所以要切换界面，减少干扰。

4. 每个页面只保留当前阶段最重要的动作。 首页最重要的是 Upload。 工作台最重要的是看结果和 Download。

5. MVP模仿的不是它有多少功能，而是它怎么引导用户完成一次完整体验。 一句话总结就是：

先让用户一眼看懂，再让用户一步开始；开始之后，就把所有注意力集中到结果上.

我的最小闭环：3 块 + Footer

第一块： 首屏核心工具。 效果演示 + 一句话文案 + Upload Image。 这是必须的。

第二块： 效果展示。 放 3～4 张Before / After 示例。 让没有上传图片的人，也马上知道效果怎么样.

API 选型：一路试错到 $0.0005

需要一个专业去背景的API。

先试了ChatGPT直接图生图去背景，结果图片会变亮、整体变大，加了"保持主体不变"也一样。 文生图、图生图的模型做不了这种精确分割的事，得找专业的去背景模型。

专业API查到的价格是 $0.01/张（Recraft、Replicate 常规款）。但我打算免登录免费用，100 个人点了我就亏 1 美元，1 万个人就是 100美元， 流量一来我就破产。

然后发现一个细节：remove.bg的低清Preview应该是自己压缩过的，不是调了两次API。 所以我只需要调一次高清 API，自己压缩出低清预览就行。

成本与免费策略

成本问题还是没解决。我发现自己陷进了一个思维定式——觉得必须免登录免费试用，不这样就不行。

小排老师：现在我的新产品，是先不做限制.尽量让更多的人体验。等用的人多了，再做限制。
总结：以服务器成本，换用户可能带来的口碑传播 => 服务成本来支付部分的推广成本

虽然如此，还是要在自己可接受的成本之下去做免费推广，前期应该以成本优先。

核心不是”要不要免登录”，而是”免登录之后怎么活下来”。 免费是一种获客手段，重点是免登录的流量进来后，变现漏斗和成本控制能不能撑住。

所以有两步操作，第一步降成本，第二步变现漏斗。

降成本的探索过程：

首先想到了自部署模型。去Hugging Face Spaces 试了BiRefNet和BRIA RMBG 2.0，效果还行，比 remove.bg差一点,但过得去。我本机 GTX 1650 只有 4GB 显存,跑不动这些模型。

那就走 Serverless 自部署？算了一笔账，Modal或RunPod 上跑一次大概10秒 ≈ $0.0016，比API便宜 5 倍。开始研究怎么部署，发现 RunPod要VISA 卡，我招商的 VISA审核没通过,问了群里，可以去其他银行办.

然后哥飞老师一句话把我拉回来了：一般用 API，不用自部署。

于是又去查了一遍去背景 API的价格，这次找到了Replicate 的51-labs Background Remover—— $0.0005/张，1000张才 $0.5。

教训：上次随口问 ChatGPT推荐去背景 API，给的最便宜是 $0.01/张；这次仔细调研，查出来 $0.0005/张，差了20倍。 调研深度不一样，成本不一样，决策也完全不一样。

定下API使用Replicate的51-labs Background Remover.

开发复盘：避免返工的 5 条经验

1、Claude 模仿复刻网站时，最好使用mcp打开浏览器去复刻，而不要使用内置浏览器，太垃圾了。复刻时，一定要让AI 考虑所有的交互状态，鼠标状态。

2、要考虑开发哪几个页面（隐私政策、服务条款、Contact），页面之间跳转是如何地，按钮的效果是如何地，一开始就要考虑清楚，一定要跟 AI 记得提。

3、最好一次性给定所有的素材，首页图标、文案内容、展示哪些图片，示例图片有哪些等等。

4、记得按照谷歌最优SEO 去开发。

5、如果有调用 API、存储数据库、R2 相关的，那么各种密钥一次性提供好，免得返工。

第一阶段：把人带进来，验证“我的产品有没有人愿意用”。

因为这个需求是已经被验证过的，所以只需要验证有没有人愿意用。 做法就是主动分发，不等 Google。

•

•

这一阶段主要看： 有没有人点进来 → 有没有人上传图片 → 有没有人连续用 → 哪类用户最喜欢用。 外链和SEO 权重只是顺带获得的。

第二阶段：明确做 SEO，把已经验证过的需求放大。

做法是先找长尾词，然后给每个有价值的词做真正能使用的落地页。

比如： remove background from logo → 做 /remove-background-from-logo remove background from product photo → 做 /product-background-remover transparent background maker → 做对应工具页。

每个页面都应该是： 关键词标题 + 直接上传使用 + 示例效果 + 简单说明 + FAQ。

然后再围绕这些页面做：

•
内链：相关工具页互相链接
•
外链：让目录、博客、资源页链接到具体页面
•
内容：补教程、使用场景、FAQ
•
GSC：看哪些词开始有曝光
•
根据曝光和点击继续扩展新长尾词

所以第二阶段的核心是：

关键词 → 落地页 → 收录 → 外链 → 排名 → 自然搜索流量。
