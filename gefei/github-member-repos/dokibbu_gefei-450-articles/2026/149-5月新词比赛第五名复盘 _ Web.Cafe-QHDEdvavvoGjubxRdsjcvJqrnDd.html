从 0 到 1 做新词站：一次新词比赛第五名的复盘

大家好，我是 Reyn，本职是算法。这次很荣幸拿到了新词比赛第五名。

我是今年一月，过年前加入社群的。刚入群时，我花了两个星期看教程，随后断断续续做了 3 个网站，但基本都没有什么起色。

决定做出海之后，我其实理性上已经预料到冷启动会很难。毕竟从 0 到 1 永远是最难的阶段。但真正执行的时候，心理上还是会难受。看着不少老哥陆续拿到结果，而我这边正反馈很少，压力确实不小。

这篇主要复盘我从入群到现在的一些经验和踩坑，希望对同样刚开始做新词站、工具站、小游戏站的朋友有一点参考。

一、前三个网站的失败复盘

1. 第一个网站：选词和域名理解都不够深

第一个网站参考的是教程里“找大站内页，再用首页 + 域名去做”的方法。

当时我对教程理解还不够深入，跟随 AI 的建议，选了一个偏品牌词方向的域名。虽然域名里用到了一部分主关键词，但现在回头看，这个选择完全没必要。

更大的问题是，这个词所在的 SERP 里，老牌工具网站权重非常高。我在没有外链积累、没有站点权重的情况下，直接去做这个词，结果可以说死得很惨。

最终表现是：

1.
排名基本在 50 名开外。
2.
曝光很少。
3.
点击几乎没有。
4.
站点没有建立任何有效正反馈。

这次失败让我意识到，新手做词不能只看“这个词有没有搜索量”，还要看当前搜索结果里是谁在排名、自己有没有机会挤进去、用户需求是否足够明确。

2. 第二个网站：小语种词看似有机会，实际需求太杂

第二个网站是我通过 Semrush 筛选 KD 后找到的一个小语种词。

当时这个词的搜索量看起来还可以，KD 也不算高，所以我觉得好像有机会。但上线之后才发现，这其实是一个非常宽泛的词，用户需求非常杂糅。

更麻烦的是，搜索结果里还有一部分政府网站。这说明 Google 对这个词的理解里，包含了比较强的官方信息需求。我的工具站页面和这个搜索意图并不匹配。

最终结果是：

1.
词本身太宽泛。
2.
用户搜索意图不集中。
3.
SERP 里有政府网站，竞争类型对我不利。
4.
网站虽然出了词，但出的词并不是我想要的方向。
5.
页面没有明显排名机会。

这次让我意识到，KD 只是辅助指标，不能单独决定要不要做。真正重要的是 SERP 结构和用户意图。

3. 第三个网站：发现了新词，但动手太晚，体验也没做好

第三个网站已经是 4 月份的事情了。

当时我通过大量阅读群里的帖子和教程，已经比较明确知道自己的问题主要还是找词。正好那段时间比赛开始，很多群友复盘时提到可以查看 vercel.app 子域名。我就按照这个方法实践了一下。

当时我发现了一个工具类新词，做完后确实有一点曝光和流量。但它和 Google Trends 里看到的量级完全不匹配。

现在复盘，主要原因有两个：

1.
这个词虽然是新词，但我做的时间已经偏晚。
2.
用户体验没有做到位。

后面我自己再去用网站时才发现，虽然我的工具页面看起来和别人差不多，但真实效果差距很大。工具类网站的核心不是页面长得像，而是结果是否真的好用、是否能解决用户当下的问题。

这个网站让我明白，做新词要快，但快不代表可以牺牲核心体验。尤其是工具站，用户进来试一次，如果结果不好，基本不会再给第二次机会。

二、第四个网站：本次获奖站点的完整复盘

第四个网站就是这次获奖的网站。

这次大部分拿到结果的群友，其实也都是做这个词。这个词我也是在 vercel.app 子域名里刷到的。

刚看到这个词时，我并不了解它是什么，于是先让 AI 帮我做了一轮解析。后来发现，这是一个被主播带火的游戏词。接着我去各个社交媒体上搜索相关视频，发现流量确实不小。

虽然当时做已经稍微有点晚，但我想起哥飞说过很多次：看到新词可以直接上，就算失败也就是一个域名钱。新词确实有红利期，但几天、一周之内通常也还有机会。

思考了一会后，我决定开始动手。

1. 早期踩坑：多 Agent 协作消耗很大，结果很差

我大概是 6 号左右开始动手的。现在回头看，当时犯了一个比较蠢的错误。

我在 X 上刷到不少关于slock（多 Agent 协作框架）的讨论，就想着用这次项目尝试一下。于是用 Claude Code 和 Codex 搭了一套前端、后端、架构、Leader 这种小 Agent 队伍来开发。

结果是：

1.
Token 消耗飞快。
2.
协作链路很复杂。
3.
产出结果很差。
4.
游戏逻辑很浅。
5.
UI 视觉很烂。
6.
因为涉及大量经典 IP 动漫人物，Codex 策略很保守，输出内容偏安全、偏抽象，最终变成了简单色块游戏。

我对比原作者网站后，很快意识到，这种结果肯定无法满足用户需求，于是放弃了这套多 Agent 协作模式。

2. 回到熟悉流程：Codex + 人工审核 + 分阶段推进

放弃多 Agent 后，我改回自己最熟悉的开发方式：Codex 半自动开发，人工强审核。

具体流程是：

1.
先用 Image 2 出几个概念图。
2.
从里面选一个自己看着顺眼的视觉方向。
3.
让 AI 复现这个界面。
4.
拆解原作者游戏逻辑。
5.
复刻原版游戏题目。
6.
再补充一些自己找到的动漫角色。
7.
用 AI 生成题库。
8.
持续人工审核和修正。

当时我想的是，题库更丰富，游戏体验可能会更好。

但后来复盘下来，我感觉这一步的实际价值没有想象中大。原因是这种游戏并不适合无限扩充题库。不是所有动漫角色图片都适合作为题目，低质量题目反而会影响体验。

我的推测是：对这类社媒起源的小游戏来说，大而丰富的题库未必能明显提升用户体验，很多时候只是开发者的自我满足。

更关键的是，用户可能是因为原版游戏、原版题目、原版讨论语境而来。如果他进入我的网站后，发现很多题目和原游戏不一样，而且质量一般，就会降低体验，也不利于和其他玩过同一游戏的人交流。

所以这类站点的题库策略，应该优先保证核心题目质量和传播一致性，再考虑扩展内容。

3. 排行榜和分享模块：适合社媒小游戏的关键功能

上线两天后，我想到可以加排行榜和分享界面。

因为这个词本身来自社交媒体，小游戏的传播方式天然依赖分享、晒分、比较和讨论。既然用户是在社媒上被种草的，那么网站内就应该尽量补齐传播链路。

于是我添加了：

1.
排行榜模块。
2.
分享模块。
3.
适合玩家晒成绩的界面。

这部分我认为是有价值的。社媒小游戏不能只做“能玩”，还要让用户有动力把结果发出去。

4. Reddit 真实反馈：用户需求出现时要快速响应

过了几天，我发现 Reddit 上有一个帖子在讨论我的网站，里面有人希望我加一个新模式。

这次我反应比较快。看完后我判断这是真实用户需求，而且实现成本可控，于是当天晚上就开发了一个新模式。

后续数据也证明，这个新模式确实拿到了一小部分流量。

这件事给我的感受很深：早期站点的用户反馈非常宝贵。尤其是 Reddit、X、TikTok、YouTube 评论区这种公开场景里的反馈，很多时候比自己闭门想功能更有价值。

三、SEO 部分的阶段性观察

关于 SEO，我目前还在摸索，没有特别确定、已经反复验证的方法。

目前我的观察是，网站流量稳定在 5.7 到 6 左右。我改过好几版 SEO 内容，但没有动 TDH。从结果看，短期作用有限。

这里可能有几个原因：

1.
SEO 反馈本身比较慢。
2.
小站权重积累还不够。
3.
页面内容优化没有触及核心排序因素。
4.
同质化 AI 文案太多。
5.
站点体验和用户行为数据可能更关键。

最近复盘时我才发现，开发过程中一些较大体量的文案修改需求，AI 经常因为上下文限制，只改了一部分就草草收尾。由于内容比较长，人工审核成本较高，我当时也没有仔细检查。

现在回头看，这是一个很典型的问题：AI 生成或修改长文案时，必须分块验收。否则很容易出现表面完成，实际大量内容没有被修复的情况。

四、外链冷启动复盘

外链这部分，一开始我做得非常曲折。

最早我是手动发外链，发了一段时间后发现效率很低。在 AI 时代，这种重复性工作全靠人工做，性价比确实太差。

后来看到哥飞在群里分享 Chrome 提交外链插件的思路，我就仿照这个方向做了一套流程。

我的大致方法是：

1.
先找目标站。
2.
再通过目标站反查外链网站。
3.
进入这些外链网站。
4.
在评论区继续发现更多可发链接的网站。
5.
用类似方法继续扩展外链池。
6.
爬取并整理外链资源。
7.
结合群友分享的方法，对外链集合做基于流量的有效 URL 分析（是否有流量，是否被标记）。
8.
做了一个批量发外链的 Agent。
9.
实装了群友分享的 dofollow 外链方法 。

从结果看，外链这块确实有用。至少对我来说，冷启动资源已经基本够用了。

这部分最大的体会是，外链建设要流程化、工具化、资源池化。纯手动发外链很难坚持，也很难形成可复用资产。

五、我的阶段性总结

1.
找词是最核心的杠杆。 新手最容易犯的错误，是只看搜索量、KD 或 Trends 热度。真正决定机会的，是 SERP 结构、用户意图、竞争对手类型、自己能不能做出匹配需求的页面。
2.
KD 只能辅助判断，不能替代 SERP 分析。 有些词 KD 看起来低，但搜索结果里可能有政府站、权威站、大平台或完全不同类型的页面。这种词对新站并不友好。
3.
新词最重要的是速度。 看到新词后，先快速判断来源、热度、社媒传播链路和用户需求。只要机会大于成本，就可以直接上。失败的成本通常就是一个域名和几天时间。
4.
做新词时要先搞清楚它为什么火。 这个词来自主播、游戏、梗图、工具需求、新闻事件，还是某个社媒挑战，决定了页面应该怎么做。只抄关键词，不理解传播背景，很容易做偏。
5.
用户体验要围绕原始需求设计。 工具站要看结果是否好用，小游戏站要看是否符合用户预期，内容站要看是否解决搜索问题。页面外观相似只能解决第一眼信任，核心体验才决定留存和传播。
6.
题库和内容扩展要克制。 内容更多不一定更好。对社媒起源的小游戏来说，题目质量、原始语境、玩家交流一致性，可能比题库数量更重要。
7.
AI 开发必须有人类强审核。 多 Agent 协作听起来很先进，但如果没有强约束、强验收和明确任务拆分，很容易变成高消耗低产出。当前阶段，我更适合 Codex 半自动开发 + 人工审核的模式。
8.
长文案修改必须分块验收。 AI 在处理大段内容时，经常只完成一部分。尤其是页面文案、SEO 内容、FAQ、教程内容，必须分模块检查，否则很容易留下大量同质化、低质量 AI 文案。
9.
外链冷启动要工具化。 手动发外链效率太低。更好的方式是建立外链资源池、分析有效 URL、筛选高质量目标，再通过插件或 Agent 辅助提交。
10.
新手阶段最重要的是持续拿反馈。 前几个网站失败很正常。每次失败都要拆清楚原因：是词错了、SERP 错了、体验错了、速度慢了、外链不够，还是页面没有满足真实需求。只要每次复盘都能提炼出一个明确问题，下一次成功率就会提高。
11.
最后，执行比想清楚所有问题更重要。 很多新词机会窗口很短。看到机会后，可以先做最小可用版本上线，再根据数据和用户反馈补功能。新词站最怕一直研究，真正开始做的时候，窗口已经过去了。

以上就是我从入群到这次比赛的一些复盘。整体来看，我现在仍然是小白阶段，SEO、站点增长、外链质量判断还有很多地方需要继续摸索。但这次至少给了我一个比较明确的正反馈，也让我确认：这条路是可以通过持续复盘和执行不断提高成功率的。
