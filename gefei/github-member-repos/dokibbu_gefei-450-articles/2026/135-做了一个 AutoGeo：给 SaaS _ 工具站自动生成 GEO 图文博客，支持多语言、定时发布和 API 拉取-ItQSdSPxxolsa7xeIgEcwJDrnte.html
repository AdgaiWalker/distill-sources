大家好，最近做了一个小工具，叫 AutoGeo ：

https://autogeoflow.com/


对，就是自动写文章的，可以根据关键词、标题、知识库 生成长图文，目标是替换网站自己的博客系统

可以设置自己的 ai key ，也可以使用系统自带的 ai

评论提供注册邮箱，送 30 积分，可以发 30 偏文章、30 个 gpt 2 插图

它主要解决一个我自己在做 SaaS / 工具站时经常遇到的问题：

产品网站上线以后，首页、Pricing、FAQ、Docs 这些页面都可以很快搭起来，但 Blog / Guide / Use Case 这类内容很难长期维护。

尤其现在除了传统 SEO，很多人也开始关注 GEO，也就是 Generative Engine Optimization，面向 ChatGPT、Claude、Gemini、Perplexity、Google AI Overviews 这类 AI 搜索 / 问答入口的内容可见度。

单纯让 AI 手动写几篇文章其实不难，难的是：

•
文章需要持续更新，不是上线时写 3～5 篇就结束
•
SaaS 网站通常需要覆盖不同关键词、使用场景、对比内容、FAQ
•
如果做海外产品，还要支持多语言内容
•
内容不能完全靠空 prompt 胡编，最好基于产品资料、FAQ、文档、案例等真实知识库
•
生成之后还要审核、发布、同步到自己的博客系统

所以我做了 AutoGeo，想把“偶尔用 AI 写一篇博客”变成一个可重复执行的 GEO 内容工作流。

目前的基本流程是：

1.
创建项目
2.
准备关键词 / 标题 / 知识库 / 图片素材
3.
选择 Prompt、语言、模型和发布节奏
4.
批量生成结构化 GEO 图文文章
5.
文章进入草稿 / 审核状态
6.
审核后发布
7.
通过 API 或 Webhook 同步到自己的站点

输入方式目前支持两类：

•
手动输入关键词或自定义标题 + 知识库
•
输入产品 URL，自动提取关键词、标题、知识库和图库素材

知识库可以是 Markdown 内容，也可以来自 URL / 产品文档 / FAQ / 页面资料。生成时会尽量围绕真实业务信息，而不是只靠一句 prompt 直接生成。

生成内容包括：

•
多语言文章
•
FAQ
•
SEO metadata
•
封面图 / 插图
•
Markdown / 结构化内容
•
可发布的博客页面数据

发布方式也做了几种：

•
可以直接在 AutoGeo 里管理文章状态
•
可以通过 API 拉取文章、分类、任务数据，接到自己的博客库
•
可以通过 Webhook 推送到自己的站
•
也开源了一个简单的 Next.js Blog Template，不想自己写前端的话，可以直接部署一个轻量博客前台

我自己觉得比较适合这些场景：

•
独立开发者做了一个 SaaS / AI 工具，但网站没有持续博客内容
•
产品站需要持续覆盖 “how to / use case / comparison / FAQ” 这类长尾内容
•
做海外站，需要同时生成英文、中文、日文等多语言内容
•
有自己的博客系统，只想把文章内容通过 API 拉回去渲染
•
管理多个小产品，希望每个产品都有自己的内容节奏

当然，这个工具不是想鼓励 批量制造低质量 SEO 垃圾内容 。

我的设计思路是：先准备可靠的知识库和素材，再用 AI 辅助生成草稿，最后保留人工审核和发布控制。也就是说，它更像一个内容生产流水线，而不是“一键生成 1000 篇文章然后直接发”。

目前功能还比较轻量，早期阶段也会尽量开放给大家试用。如果你也在做 SaaS / 工具站，刚好有“博客内容太少、长期更新很麻烦、多语言不好维护”的问题，可以试试看。
