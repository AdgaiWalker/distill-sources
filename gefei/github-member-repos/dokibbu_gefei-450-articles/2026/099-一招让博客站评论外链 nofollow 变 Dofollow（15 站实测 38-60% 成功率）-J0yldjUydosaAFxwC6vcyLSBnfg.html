2026-04-15 验证成功。这是把 WordPress 评论里的 nofollow 变成 Dofollow 目前唯一已知的方法，社群里应该还没人分享过，今天把完整做法加上实测数据贡献出来。

背景

这两天在做游戏站的外链，手动发 WordPress 评论时，在一个博客的评论区注意到一件怪事：明明是普通的 WP 评论区，但有一条老评论的链接竟然是 Dofollow。

右键检查 HTML，发现那条链接的 href 里多了一个换行符 \n 。这就让我联想到 WordPress 加 nofollow 的函数可能用了正则，于是去翻了一下 WP 源码。

原理

WordPress 核心文件 wp-includes/formatting.php 里的 wp_rel_nofollow() 函数，用这个正则匹配 <a> 标签并添加 rel="nofollow" ：


代码块
PHP
$text = preg_replace_callback('|<a (.+?)>|i', 'wp_rel_nofollow_callback', $text);

注意 .+? 这个写法，它默认不匹配换行符，而且这个正则 没有加 /s (DOTALL) flag 。

所以只要我们在 href 属性值里塞一个换行符 \n （charCode 10），整个 <a> 标签就不会被正则匹配到，nofollow 不会被添加，链接默认是 Dofollow 。

具体做法

在评论正文的 textarea 里（注意是 正文 ，不是 author URL 字段），写：


代码块
HTML
text before <a href="https://target-site.com/
">Anchor Text</a> more text

关键点： \n 必须是真实的换行符（charCode 10），不是字面量的 \n 两个字符。

如果你手动在评论框里敲，直接按 Enter 把 \n 打进去就行。如果用 Playwright / Puppeteer 等工具，JS 字符串 '\n' 会自动转成 charCode 10，不用做什么特殊处理。

验证是否真的打进去了：


代码块
JavaScript
const textarea = document.querySelector('textarea[name="comment"]');
const idx = textarea.value.indexOf('site.com/') + 9;
console.log(textarea.value.charCodeAt(idx) === 10); // true = 成功

⚠️ author URL 字段 bypass 不到
评论框上面那个 website / 网址 字段（author URL），无论怎么填，WP 都会单独给那个链接加 nofollow，和这个 bypass 没关系。 只有正文里用 <a> 标签的 bypass 才有效 ，别在 author URL 字段上浪费时间。

完整 SOP

1.
导航 到目标文章页。
2.
检查表单字段和反垃圾系统 （下文"失败模式"章节会讲怎么识别）。
3.
如果有 CleanTalk 或 Jetpack Highlander 直接跳过这个站。
4.
如果有 随机名 honeypot textarea （比如 ak_hp_textarea 、 alt_s 、 wantispam_e_* 这类乱七八糟的 name），这些字段必须留空。
5.
⚠️ Playwright 坑 ：如果用 evaluate 直接设 textarea value，不会触发 React / Vue 的 onChange 事件，站长的 anti-spam 逻辑会识别到异常。正确做法是用 pressSequentially(delay) 把字符一个个敲进去，然后用原生 click() 提交。
6.
正文填 <a href="url\n">Anchor</a> 。
7.
如果遇到 name="submit" 冲突导致 JS 无法提交，用原生方法：


代码块
JavaScript
HTMLFormElement.prototype.submit.call(document.querySelector('form'))

8.
原因：很多 WP 评论表单的提交按钮是 <input type="submit" name="submit"> ，这个 name 会 shadow 掉 form 对象的 submit() 方法，导致 form.submit() 报错。用原型链上的 submit 绕过 shadow。
9.
检查返回 URL ：
◦
#comment-XXX = 秒过，立刻可见
◦
?unapproved=XXX = 进了审核队列
◦
#comment-XXX = 秒过，立刻可见
◦
?unapproved=XXX = 进了审核队列
10.
秒过的立刻 验证 rel 属性 ：


代码块
JavaScript
document.querySelector('a[href*="你的域名"]').rel

11.
判断结果：
◦
空字符串 ✅ 纯 Dofollow （最好的情况）
◦
external noopener noreferrer ✅ 仍是 Dofollow （无 nofollow 无 ugc）
◦
ugc ❌ 失败 （见下面"ugc 的坑"）
◦
nofollow 或 nofollow ugc ❌ 失败
◦
空字符串 ✅ 纯 Dofollow （最好的情况）
◦
external noopener noreferrer ✅ 仍是 Dofollow （无 nofollow 无 ugc）
◦
ugc ❌ 失败 （见下面"ugc 的坑"）
◦
nofollow 或 nofollow ugc ❌ 失败
⚠️ ugc 的坑 —— 不要被假成功骗了
WP 5.3+ 默认会给评论外链加 rel="ugc" （Google 2019 引入的新属性）。ugc 和 nofollow 一样 不传递权重 。所以 bypass 掉 nofollow 但还剩 ugc = 没用 。
验证时 rel 必须是空字符串，或者只有 noopener / noreferrer 这类与权重无关的属性，才算真正成功。

前提条件

1.
WP 站 wp_kses 必须允许 <a> 标签 — 有些站配置了 strip 会直接把 a 标签删掉
2.
评论能发出来 （Akismet 通过 / 无审核 / 站长审核通过）
3.
没有额外的 sanitize 插件 在 wp_rel_nofollow() 之后再加 nofollow

实测成功率

•
A 站 13 个评论站：5 Dofollow 秒过 = 38%
•
B 站 10 个评论站：6 Dofollow 秒过 = 60%
•
0 个被 Akismet 静默吞掉
•
失败主要来自 wp_kses strip 和 CleanTalk 拦截

意外发现：第三方插件也可能被 bypass

有些站用了 WP External Links 之类的插件给外链加 nofollow，但 这些插件也常常用类似的正则 。结果是插件的正则也被 \n bypass 掉，rel 最后变成 external noopener noreferrer （ 连 nofollow 都没有 ）。

所以别看到站点有第三方 SEO / Anti-Spam 插件就直接跳过，值得测一下。

2.

3.
避开 ：hCaptcha 站、Jetpack iframe 站、CleanTalk 站

情报挖掘方法论（可推广）

这次的发现其实是一个方法论： 从大平台的出站 Dofollow 链接逆向分析手法 。

具体步骤：

1.
Ahrefs 选高 DR 站 → 看 Outgoing links → 过滤 Dofollow
2.
找" 不应该是 Dofollow "的评论区链接（一般 UGC 评论都该是 nofollow）
3.
检查 HTML： document.querySelector('a[href*="target"]').outerHTML
4.
寻找 href 中的异常字符（ \n / \r / \t 或其他 unicode）
5.
对照平台 sanitize 函数源码 → 找正则缺陷 → 自己也能复用

同样的思路可以推广到 Drupal / Joomla / Ghost / Discourse 这些其他平台。只要平台的 sanitize 逻辑用了正则，并且正则对换行或特殊字符处理不严，就可能有类似的空子。

总结

•
原理 ：WP wp_rel_nofollow() 正则 |<a (.+?)>|i 没加 /s flag， .+? 不匹配换行符
•
做法 ：评论正文里 <a href="url\n">Anchor</a> 塞一个 \n
•
成功率 ：38% - 60%（取决于选站精度）
•
前提 ： wp_kses 允许 <a> 标签 + 无额外 sanitize + 无 Jetpack iframe / CleanTalk
•
验证 ：rel 必须是空字符串或只有 noopener / noreferrer，有 nofollow 或 ugc 都算失败
•
意义 ：WP 评论外链从 nofollow 全部变成 Dofollow，价值质变

这手法一旦被大规模滥用，WP 官方大概率会修这个正则（加 /s flag 就完事了）。所以有能力的朋友 现在就用 ，趁窗口期。
