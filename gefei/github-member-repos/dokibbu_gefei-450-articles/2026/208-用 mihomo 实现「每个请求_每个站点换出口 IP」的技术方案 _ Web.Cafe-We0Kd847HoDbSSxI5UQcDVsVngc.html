今天有群友问是如何实现出口 ip 自动切换的，我就让 kimi 整理了我的自用方案，想想也行还有别人也有同样的需求，就发到这里了。

用途：浏览器自动化、批量投放、采集等场景需要逐站轮换出口 IP。 这份文档自包含，直接交给 AI 助手（如 Kimi）即可照做。 核心事实：mihomo(Clash.Meta 内核)自带 RESTful API,可以 动态 切换代理组的选中节点

1. 架构


代码块
JavaScript
你的脚本/浏览器 ──► 127.0.0.1:7891(mihomo 混合代理端口)
│
▼
代理组 ROTATE(select 类型,当前选中某个节点)
│
▼
订阅里的几十个国家节点(日/港/台/新/美…)

控制面:127.0.0.1:9091(mihomo external-controller,RESTful API)
PUT 一下就能换 ROTATE 当前选中的节点 → 出口 IP 立刻变

2. 前提

•
安装 mihomo(Clash.Meta 内核, mihomo -d <配置目录> 常驻)。
•
一份 多节点订阅 (机场订阅链接,几十上百个节点最佳)。
•
配置文件 config.yaml 关键三段:


代码块
YAML
mixed-port: 7891 # http/socks 混合入口,流量走这里
external-controller: 127.0.0.1:9091 # RESTful API,控制面
# secret: 'your-token' # 建议设置;设了之后每个请求带 Header Authorization: Bearer <token>

proxy-providers: # 订阅来源
sub:
type: http
url: "你的订阅地址"
interval: 86400
path: ./providers/sub.yaml

proxy-groups:
- name: ROTATE # 组名随意,后面 API 用它
type: select # select = 手动选中,可用 API 改选中项
use: [sub] # 引用订阅里全部节点

3. 三个 API 就够(全程 HTTP,无需重启)

设了 secret 就加请求头 Authorization: Bearer <token> ;没设就直接调。


代码块
Bash
# ① 看 ROTATE 组里有哪些节点 + 当前选中
curl http://127.0.0.1:9091/proxies/ROTATE
# → {"alive":true,"all":["🇯🇵 日本 01","🇭🇰 香港 03",...],"now":"🇯🇵 日本 01"}
# 把 all 列表存下来当轮换池,比如 /tmp/mihomo_nodes.json

# ② 切换选中节点(立即生效,204 无 body)
curl -X PUT http://127.0.0.1:9091/proxies/ROTATE \
-H 'Content-Type: application/json' \
-d '{"name":"🇭🇰 香港 03"}'

# ③ 走代理验证出口 IP 确实变了
curl -x http://127.0.0.1:7891 https://api.ipify.org

节点名带 emoji/空格时,逐节点 API 要 URL 编码路径段(urllib.parse.quote(name, safe=''))。

4. 批次轮换的标准写法(Python,实测可用)


代码块
Python
import json, requests, sys

nodes = json.load(open('/tmp/mihomo_nodes.json')) # 上面 ① 的 all 列表
CTRL = 'http://127.0.0.1:9091'
PROXY = {'http': 'http://127.0.0.1:7891', 'https': 'http://127.0.0.1:7891'}
state = {'i': 0}

def rotate():
"""每次调用切到下一个节点;死节点跳过;连续 8 个全死才中止(防止代理故障期白烧目标)。"""
for _ in range(8):
name = nodes[state['i'] % len(nodes)]
state['i'] += 1
try:
requests.put(f'{CTRL}/proxies/ROTATE', json={'name': name}, timeout=8)
ip = requests.get('https://api.ipify.org', proxies=PROXY, timeout=10).text
return f'{name}({ip})' # 切成功,返回出口 IP 供日志
except Exception:
continue # 死节点,跳下一个
sys.exit('连续 8 节点全死,中止批次')

for site in sites:
exit_info = rotate() # 每个目标前换一次
print(site, '⇠', exit_info)
# … 用 PROXY 访问目标 …

要点: 每次切换后用 ipify 实证出口 IP ,不要只信 PUT 返回 204——204 只代表选中成功,不代表那个节点真能通。

5. 接到浏览器自动化(Playwright)


代码块
JavaScript
// 整个浏览器走 mihomo;切节点后新开的 page/context 就用新出口
const browser = await chromium.launch({
headless: false,
proxy: { server: 'http://127.0.0.1:7891' },
});

切换时机:脚本先 PUT /proxies/ROTATE (Node 里用 fetch 调同样的 API),ipify 确认后再开页面。

6. 坑(全是踩过的)

1.
切换是全局的 :ROTATE 组同一时刻只有一个出口。多个并发任务会互相抢出口——要么串行,要么建多个 select 组 + 多个端口。
2.
节点会死 :订阅里总有一部分节点是死的(我们实测 71 个里 10 个 SSL 全灭)。所以 rotate 必须带「跳过 + 连续全死才中止」,别重试同一个死节点。
3.
健康检查别用错接口 :部分 mihomo 版本没有 GET /proxies/{name}/delay (返回 404)。可靠的体检法就是「切过去 + 拉 ipify」。
4.
出口 IP ≠ 万能 :数据中心 IP 照样被 CleanTalk/Cloudflare 按 IP 信誉拒;需要住宅 IP 时这套不解决,那是另一条线。
5.
和打码/solver 服务联用时注意一致性 :solver 解 token 的出口 IP 若与浏览器出口 IP 不一致,严格站点会判 token 无效(报 ERROR_INVALID_TASK_DATA 之类)。
6.
订阅会过期/流量会跑完 : GET /proxies/ROTATE 返回里通常带订阅信息(到期时间、已用流量),值得每天看一眼。
7.
本机调试 API 时 : curl 记得 --noproxy '*' 或确认没走系统代理,否则你连 9091 都会被代理出去。

7. 一分钟自检清单


代码块
Bash
curl --noproxy '*' http://127.0.0.1:9091/proxies/ROTATE | head -c 200 # 控制面活着
curl -x http://127.0.0.1:7891 --max-time 10 https://api.ipify.org # 数据面通着
curl --noproxy '*' -X PUT http://127.0.0.1:9091/proxies/ROTATE \
-H 'Content-Type: application/json' -d '{"name":"随便挑个节点名"}'
curl -x http://127.0.0.1:7891 https://api.ipify.org # IP 变了 = 成了
