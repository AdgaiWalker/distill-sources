Cloudflare Pages 如何返回 410 Gone（\_redirects 不支持的坑）

背景

注册了一个域名，准备搭个新站。上线后发现 Google Search Console 里冒出一堆奇怪的 404 错误——URL 都是 /post/xxx 、 /category-xxx 这种 WordPress 典型路径。一查才知道这域名之前被别人用过，前主人用 WordPress 搭的站，Google 还保留着旧页面的索引。

搜索引擎看到这些旧 URL 返回 404 会反复重试，不如直接告诉它「这内容已经永久没了」——也就是返回 410 Gone。

坑：_redirects 只支持 3xx

第一反应是在 _redirects 里写：


代码块
JavaScript
/post/* 410
/category-* 410

部署后发现完全不生效——访问这些 URL 仍然返回 404。

查了 Cloudflare Pages 文档 才发现： _redirects 文件只支持 301、302、303、307、308 这五种 3xx 状态码 。写 410 会被静默忽略，没有任何报错提示。Cloudflare Pages 文档

顺便还发现测试用的 301 也没生效——因为格式写反了：


代码块
JavaScript
/test-redirect 301 / ← 错误：目标路径和状态码顺序颠倒了
/test-redirect / 301 ← 正确：源路径 → 目标路径 → 状态码

解决：Cloudflare Pages Functions

用 Cloudflare Pages Functions 写一个 catch-all 中间件，放在项目根目录 functions/[[path]].js ：


代码块
JavaScript
'/.IGV0hOcNusVJOgqoD1HuWTk0PssdueKB',
];

export async function onRequest(context) {
const { pathname } = new URL(context.request.url);

if (GONE_PATTERNS.some((p) => p.test(pathname))
|| GONE_EXACT.includes(pathname)) {
return new Response('410 Gone — This content has been permanently removed.', {
status: 410,
headers: { 'Content-Type': 'text/plain; charset=utf-8' },
});
}

return context.next();
}

•
匹配到旧 WordPress URL → 返回 410
•
其他请求 → context.next() 透传给静态资源，正常页面不受影响

部署

functions/ 目录放在项目根目录，不在 src/ 或 public/ 里。Cloudflare Pages 部署时自动检测到 functions/ 目录并启用 Functions 运行时，不需要额外配置。
