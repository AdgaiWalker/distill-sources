一个目录站月入 1.3 万美元，靠的是把抄袭者变成客户

大家好，我是哥飞。

OpenAlternative 是一个开源软件替代品目录站。

你也可以把它理解成一个更细分的软件导航。

创始人 Piotr Kulpinski 最开始只是给自己整理一份开源工具列表，方便找商业软件的替代品。2024 年 2 月，他用一个周末把这份列表做成公开网站。第一版很简单，手动收集约70 个项目，按分类列出来，连复杂筛选、账号系统、后台都没有。

上线第一周，网站来了超过 10 万访问。

两年后，OpenAlternative 单站年化收入已经到了约 8 万美元。再加上后来做出来的目录站模板 Dirstarter，两个产品合计月收入在 1.2 到 1.3 万美元量级。

这个目录站跑出的结果

这个案例适合讲给大家看，所以哥飞就来跟大家聊聊这个站。

目录站大家都知道，听起来也不性感。但这个案例跑出了一条很完整的路径：先做一个有真实搜索需求的目录，再用数据和更新把页面做好，然后卖广告、赞助、付费推荐位，最后把搭目录站的方法打包成模板产品。

目录站不新，需求一直在

OpenAlternative 做的事情很好理解：帮用户找到商业软件的开源替代品。

比如有人想找 Notion 的开源替代品，想找 Airtable 的开源替代品，想找 n8n、Cursor、Power BI 这类工具的替代品。这个时候，用户需要一份能直接筛选、对比、跳转的目录。

OpenAlternative 首页就很直接，导航里有替代品、分类、技术栈、自托管、提交项目、广告合作。

OpenAlternative   首页

这类站的价值，在于帮用户少做搜索和筛选。

如果你只是写一篇“十大开源工具推荐”，它很快就过时。目录站不一样，每个项目都可以有独立页面，每个分类都可以继续拆，每个热门商业软件都可以对应一组开源替代品。

这样一来，用户搜索的每一种具体需求，都有机会变成一个入口。

第一版简单到只有列表

很多人做网站，容易一开始就想太多。

要不要账号系统？要不要用户提交？要不要评分？要不要评论？要不要后台审核？要不要付费功能？

OpenAlternative 第一版没有这么复杂。

用 Astro 做前端，用 Airtable 当数据库，用 Tailwind CSS 做样式。真正花时间的地Piotr

方，是手动收集约 70 个开源项目。项目来源包括 Google、Reddit、GitHub 趋势页，还有他自己作为开发者的经验。

他的筛选标准也很朴素：项目要有人用，要还在维护。

目录站真正麻烦的地方，是收录一堆没人用、没人维护、没有判断标准的东西。那样页面再多，也只是低质量列表。

第一版只做一件事：把商业软件的开源替代品按分类列出来。

这就够了。

先用最小版本验证需求，等真的有人用，再决定下一步补什么功能。

第一波流量来自社区，长期流量来自搜索

OpenAlternative 发布到 X 的时候，Piotr 只有大约 700 个关注者。

但这个选题天然适合开发者社区传播。后来它在 Reddit 和 Hacker News 被更多人看到，上线第一周访问量超过 10 万。

第一波流量有运气成分。真正能让网站长期跑下去的，是后面的搜索流量。

OpenAlternative 的搜索页面拆得很细：

每个开源项目一个页面。

每个分类一个页面。

每种编程语言、技术栈、自托管维度都可以做页面。

每个商业软件，都可以对应“某某工具的开源替代品”页面。

目录站的页面矩阵

这里面最有价值的，是“某某工具的替代品”这类搜索。

用户搜这种词，意图很明确。他已经知道自己想替换什么，只是在找可用选项。

这也是目录站适合 SEO 的原因。它可以把一个大需求拆成很多小页面，每个页面解决一个具体问题。

目录站要有数据，不能只是一堆链接

还有一个很值得学的动作：自动更新项目数据。

OpenAlternative

它会拉 GitHub 数据，比如 stars、forks、open issues、last commit、tags 等。用户看到一个项目时，不只看到名字和简介，还能看到这个项目是否活跃、有没有人在维护、社区热度怎么样。

这对目录站很重要。

一个项目三年没更新，和一个项目上周刚发布新版本，用户判断完全不一样。

所以目录站真正的内容，应该包含能帮助用户做选择的信息，不能停在标题、简介和链接。

对搜索引擎来说，页面也不会一直停在老状态。项目数据持续更新，页面就有了新鲜度。

Piotr 后来也把这个思路继续往前推，用自动化工具处理内容更新、社媒发布、项目提交审核等重复工作。这样一个目录站才有可能长期维护，而不把人拖死。

有流量也不要急着收钱

OpenAlternative 早期犯过一个很典型的错误。

第一波流量起来后，Piotr 很快在网站上放了一个 97 美元的付费链接。结果 Reddit 社区很反感，觉得这个开源目录带着太强的销售味。

他很快把付费链接撤掉。

接下来接近一年，他都没有继续强行变现，重点放在增加项目、优化分类、回应用户建议、把目录做得更有用。

这个选择看起来慢，但对开源社区很关键。开发者对商业味太重的东西很敏感，你刚出现就收钱，很容易把信任打掉。

等网站真的有持续访问和用户信任后，再做广告、赞助、付费推荐位，接受度就高很多。

OpenAlternative 后来的收入结构比较清楚：广告和赞助约占 65% ，付费推荐位约占35% 。付费推荐位的价格约 197 美元 / 月。

目录站怎么变现

为什么会有人愿意付费？

因为 OpenAlternative 的用户很垂直，是一批正在寻找软件替代品的开发者和技术决策者。对工具厂商来说，这批人有商业价值。

做目录站，别只盯着访问量。

更重要的是问清楚：谁会为了出现在这个目录里付费？他为什么愿意付费？用户点进去之后，对被推荐项目有没有价值？

被复制以后，反而看到了新产品

这个案例最有意思的一步，是 Dirstarter。

OpenAlternative 一开始就是开源的，代码公开在 GitHub 上。网站跑起来后，类似站点不断出现。很多人直接复制设计、复制概念，换个名字上线。

换成很多人，第一反应可能是生气。

Piotr 后来的处理方式更聪明：既然这么多人想做目录站，那就把目录站的代码、支付、后台、SEO、AI 内容生成、文档整理成一个正式产品，卖给想做目录站的人。

于是 Dirstarter 出来了。

它属于目录站建站模板，不能按传统订阅软件来理解。官网展示的卖点包括内置支付、管理后台、登录、博客、AI 内容、SEO 页面、广告和付费位置等。购买一次，就可以用来启动自己的目录站。

Dirstarter 在 2025 年 2 月上线。创始人后来的复盘里提到，它已经做到约 5000 美元 / 月，官网也展示了 200 多客户。

被复制后看到新需求

这一步很值得琢磨。

别人复制你的站，说明页面本身很容易被复制，也说明市场里有一批人想做类似东西。

如果你只卖一个目录站，复制者是麻烦。

如果你把建目录站的方法打包好，复制者就成了潜在客户。

普通人能学什么

这个案例不适合照抄 OpenAlternative。

开源替代品这个方向已经有了比较强的项目，普通人再复制一个同类站，很难做出差异。

但它背后的选题方法可以学。

如果你想做目录站，可以先问自己几个问题。

第一，用户会不会主动搜索这类替代方案？

比如“某某工具替代品”“某某地区某某服务”“某某行业工具列表”“某某功能开源方案”。搜索词越具体，用户意图越清楚。

第二，被收录对象的信息能不能公开整理？

目录站冷启动，最怕一开始没有内容。如果对象信息本来就在官网、GitHub、商店页、公开资料里，你就有机会先把基础库搭起来。

第三，每个对象能不能独立成页？

只有列表页，SEO 入口有限。每个工具、每个服务商、每个项目、每个分类都能独立成页，搜索入口才会越来越多。

第四，数据能不能持续更新？

像 OpenAlternative 这种站，可以用 GitHub 数据判断项目活跃度。有些行业可以用价格、评分、库存、地区、发布时间、服务范围等字段更新。只要页面持续变化，它就有长期维护价值。

第五，被收录的一方有没有付费动机？

目录站最后通常要向想曝光的一方收费。可以是广告位、赞助位、付费推荐位、排名靠前、专属页面，也可以是帮他们搭网站、做内容、做搜索优化。

回过头来看，OpenAlternative 这个案例不能被简化成“目录站一定赚钱”。

真正值得学的是：先找一个有明确搜索需求的目录站方向，把内容和数据做好，再去找商业位置。等你自己跑通过一遍，还可以把方法、代码、流程整理成产品。
